# KiraCode V2.0 架构说明

## 1. 总体架构

Clean Architecture 三层 + MVVM，单向依赖 `ui → domain ← data`：

```
┌─────────────────────────────────────────────────────────┐
│ UI 层 (Compose)                                          │
│  ChatScreen ─ ChatViewModel(工作区状态机)                 │
│    ├ PendingOpsPanel（代理人确认队列）                    │
│    ├ WorkspaceCardSheet（世界书/正则编辑）                │
│    └ DynamicIslandInputBar / ContextFloatingPanel        │
│  ImportCard / Generate / Edit / Export / ModelConfig …   │
└──────────────┬──────────────────────────────────────────┘
               │ UseCase / 引擎调用
┌──────────────▼──────────────────────────────────────────┐
│ Domain 层（纯 Kotlin，可单测）                            │
│  ChatEngine          对话编排：历史装配→SSE→事件流         │
│  CardOpsParser       card-update 协议 → List<CardOp>     │
│  CardOperationApplier 纯函数应用到 CharacterCard          │
│  StCardCodec         v1/v2/v3 无损编解码（rawData 保真）  │
│  PngTextChunkCodec   PNG tEXt 读写                       │
│  BuiltinSystemPrompt 模式感知内置提示词                   │
│  SummarizeContextUseCase 上下文总结                       │
└──────────────┬──────────────────────────────────────────┘
               │ 接口实现
┌──────────────▼──────────────────────────────────────────┐
│ Data 层                                                  │
│  Room v4：character_cards/drafts/sessions/messages/      │
│           reference_cards（迁移链 1→2→3→4）              │
│  DataStore：API 配置组/自定义提示词/UI 偏好               │
│  RealApiService：chatCompletion(Stream) + models         │
│  KiraCodeHttpServer：Ktor Netty 前台服务                 │
└─────────────────────────────────────────────────────────┘
```

## 2. 关键模块

### 2.1 无损数据保真（StCardCodec）

**问题**：SillyTavern 卡片生态存在大量第三方扩展字段；朴素的结构化建模会在往返中丢失它们。

**方案**：分层 raw 保全。
- `CharacterCard.rawData: JsonObject?` —— 导入时保存线格式 `data` 整体
- `StBookEntry.raw / StCharacterBook.raw / StRegexScript.raw` —— 各层级原始对象
- 编码 = 以 raw 为底座、规范字段覆盖、未知键原样保留
- Room 以 `rawJson` 列持久化 rawData（世界书/正则以编码后线格式入列，读回再 decode 还原 raw）

**验证**：`StCardCodecTest.roundtrip preserves unknown extension fields` 断言
未知顶层字段、depth_prompt、正则自定义字段在两次往返后逐字保留。

### 2.2 Agent 操作协议

AI 不输出整卡 JSON（避免转义错误与覆盖风险），改为输出结构化操作块：

```
```card-update
[field:name]…[/field]
[book.add] keys:… content:… [/book.add]
[regex.delete name=x]
```
```

- **解析** `CardOpsParser`：块级正则 + 键值行解析（content 支持多行）
- **应用** `CardOperationApplier`：纯函数 `apply(card, ops): card`
- **执行策略** 由 ChatViewModel 分派：
  | 模式 | 行为 |
  |------|------|
  | CHAT | 注入只读提示词，操作不产生 |
  | AGENT | 操作进入 `WorkspaceState.pendingOperations`，UI 弹出确认面板 |
  | AUTO | 立即应用 + toast |

### 2.3 ChatEngine（对话引擎）

```
send(sessionId, content, workingCard, refs, mode)
  → resolveActiveConfig()      # 激活模型配置 > 旧版单配置 > null(报引导错)
  → 装配 system prompt：内置协议+自定义规则+会话提示+摘要+工作卡JSON+参考卡画像
  → 历史 40 条(user/assistant)
  → RealApiService.chatCompletionStream(SSE)
  → ChatEvent.Delta* → Completed(fullText, operations, promptTokens, completionTokens)
```
助手消息以**完整原文**入库（含操作块），保证下一轮上下文连续；
UI 层展示时用 `stripUpdateBlocks` 只显示自然语言。

### 2.4 工作区持久化

`sessions` 表新增三列（Migration 3→4）：
- `workingCardJson` —— 工作卡线格式 JSON（恢复会话即恢复卡现场）
- `workMode` —— CHAT/AGENT/AUTO
- `selectedReferenceIdsJson` —— 参考卡 UUID 列表（跨设备稳定标识）

参考卡多选通过进程级 `ReferenceSelectionBus` 从仓库页广播回聊天页。

### 2.5 PNG 双向通道

- 写：Canvas 渲染卡面 → PNG → 在 IEND 前插入 tEXt(`chara`=Base64(JSON)；v3 追加 `ccv3`)
- 读：扫描 chunk 流提取 tEXt → ccv3 优先 → Base64 解码（兼容未编码原文）→ StCardCodec
- 同名旧块先剥离再插入，避免重复

## 3. 数据库版本链

| 版本 | 变更 |
|------|------|
| 1→2 | 新增 sessions/messages/reference_cards |
| 2→3 | character_cards/drafts/reference_cards 增加 characterBookJson/regexScriptsJson/rawJson |
| 3→4 | sessions 增加 workingCardJson/workMode/selectedReferenceIdsJson |

均使用 `ALTER TABLE ADD COLUMN ... DEFAULT`，老数据无损升级。

## 4. 测试策略

- 单元测试 20 例：编解码往返 ×8、PNG chunk ×6、操作协议 ×6
  （PngTextChunkCodec 采用 java.util.Base64 保证 JVM 可测）
- 手工自测路径：导入 v2 样例 → 工作卡面板查看世界书/正则 → 对话修改 → 导出 JSON/PNG → 再导入比对

## 5. 已知边界

- URL 传卡参数（working_card_json）对超大卡（>1MB）可能受导航栈限制，建议常规卡使用
- 缓存命中率为估算值（上一轮 prompt 复用比），未解析各厂商 usage.cached_tokens 细节
- HTTP 服务端沿用 V1.x API 面，未与 V2 操作协议打通
